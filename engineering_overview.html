How the dashboard is built

This page covers the data and software side of the Climate Model Evaluation Dashboard. It shows how output from three Destination Earth IFS-FESOM experiments on HEALPix grids, an ERA5 reference in a cloud Zarr store and the workflow's own job reports are reduced on the HPC system into small tables and figures. A generator script then turns those into a static website, which is why the live dashboard runs without any access to the raw model data.

3. Problems the pipeline had to solve

data volume

Never hold 25 years at once

Period means are built as a running sum: one monthly GRIB file is read, added and dropped. Memory stays at one field, however long the period.

gaps

Missing months are counted

Months without a file are skipped and counted, a warning reports how many, and the mean is divided by the months actually used. GRIB fill values are turned into NaN first.

grids

HEALPix to maps

NSIDE is worked out from the number of pixels, and nested or ring order is a command-line switch. Values are then interpolated to a 0.5° grid with healpy for plotting.

reference data

ERA5 without a download

ERA5 is opened lazily as Zarr from the DKRZ Swift object store with 12-month chunks. Only the selected period is averaged, and both lat-lon and HEALPix layouts are handled.

robust parsing

Fail early on bad reports

The job-report reader checks that every required column is present and stops with a clear message listing what is missing and what was found.

deployment

A site that needs no data

The website is plain HTML built from CSVs and PNGs, so it can be served from GitHub Pages and stays fast. Every script takes its paths and limits as command-line arguments.

5. What could come next

IdeaWhy
Shared moduleReading GRIB, NSIDE inference and HEALPix regridding are repeated in several scripts. One package would remove the copies.
Tests and CIThere are no automated tests yet. The job-report parser and the period-mean code are easy to test with small files.
Automatic rebuildA GitHub Action could regenerate the HTML from the CSVs on every push, so the site and the data never drift apart.
More variablesThe same pattern (stream, regrid, tabulate, publish) can add ocean and cloud diagnostics with little new code.

6. In one sentence

Monthly HEALPix GRIB output from three IFS-FESOM experiments, ERA5 from a cloud Zarr store and Autosubmit job reports are streamed and reduced on the HPC system into eight small tables and a set of maps, and a generator script publishes them as a static dashboard that needs no access to the raw data.
